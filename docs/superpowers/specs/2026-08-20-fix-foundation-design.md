# Починка фундамента «Дисциплины»

Дата: 2026-08-20

## Контекст

Приложение — локальный трекер привычек на Expo SDK 54 (expo-router, zustand+persist,
reanimated 4, react-native-svg), ~2900 строк TypeScript. В git нет ни одного коммита:
весь код лежит в индексе и в untracked. `npx tsc --noEmit` проходит чисто.

При изучении кода нашлось девять проблем. Эта спека закрывает те из них, что дают
**неверное поведение или неверные числа**, плюс замену типографики. Рефакторинг,
оптимизация и заведение тестовой инфраструктуры сознательно оставлены на потом.

## Объём

Внутри:

1. Экран «Сегодня» вне группы табов — таббара нет вообще.
2. Правка цели переписывает прошлое.
3. `resetAll` не отменяет запланированные уведомления.
4. Заморозка проверяется только в UI; проверка семи дней ломается на переходе DST.
5. «Лучшая серия» в профиле показывает не лучшую серию.
6. Замена типографики на более выразительную.
7. Версия SDK в `README.md` и `AGENTS.md` не соответствует реальной.

Вне объёма (зафиксировано, чтобы не расползлось):

- разбиение `HabitFormSheet` (516 строк);
- мемоизация `streakOf` / `bestStreakOf` / `YearHeatmap`;
- вычистка мёртвого кода (`Chip`, `radii`) и захардкоженных радиусов;
- тесты и конфиг eslint;
- апгрейд Expo 54 → 57;
- снимок `unit` в записи дня (см. «Принятые ограничения»).

## 1. Маршрутизация

`src/app/index.tsx` переносится в `src/app/(tabs)/index.tsx`. Содержимое файла
не меняется: все импорты идут через алиас `@/`.

Причина сбоя: группа `(tabs)` не влияет на URL, поэтому `src/app/index.tsx` был роутом
`/` прямо в корневом Stack — то есть рендерился вообще без таббара. Внутри группы роута
`index` не существовало, хотя `src/app/(tabs)/_layout.tsx:20` объявляет
`<Tabs.Screen name="index">`; Expo Router на такое сообщает
«No route named "index" exists in nested children».

После переноса у корневого Stack остаётся единственный ребёнок — группа `(tabs)`, `/`
разрешается в `(tabs)/index`, и все четыре вкладки («Сегодня», «Календарь»,
«Статистика», «Профиль») становятся настоящими вкладками. Типы `.expo/types`
перегенерируются при следующем `expo start`.

## 2. Снимок цели в записи дня

Сейчас `isDone` сравнивает записанное значение с **текущей** целью привычки
(`src/lib/habits.ts:41`). Поднял цель с 30 до 50 — прошлые выполненные дни задним числом
становятся невыполненными, серия и тепловая карта переписываются. Тот же изъян в
отображении: `HabitDetailSheet` за прошлый день рисует `40 / 50 стр`, хотя цель тогда
была 30.

Решение — хранить в записи дня цель, действовавшую в момент записи.

**`src/types/habit.ts`**

```ts
export interface DayEntry {
  value: number;
  done: boolean;
  target?: number;        // цель, действовавшая в момент записи
  completedAt: number | null;
}
```

Поле опционально: у типа «галочка» цели нет, а у записей, созданных до миграции, её
неоткуда взять.

**`src/lib/habits.ts`**

```ts
export const isDone = (c: Completions, h: Habit, key: string) => {
  const e = entryOf(c, h.id, key);
  if (!e) return false;
  return h.type === 'check' ? e.done : e.value >= (e.target ?? h.target);
};
```

**`src/store/habits.ts`**

- `setProgress` пишет `target: habit.target` вместе со значением.
- `toggleCheck` поле не пишет: для «галочки» `isDone` смотрит на флаг `done`.
- `updateHabit`: если изменились `target` или `type`, запись **сегодняшнего** дня
  перештамповывается под новую конфигурацию привычки. Прошлые записи не трогаются
  никогда.
- Миграция persist `version: 2 → 3` проходит по существующим записям привычек **не**
  типа «галочка» и проставляет им `target` текущей цели их привычки. Записи «галочек»
  не трогаются: у них цели нет.

Перештамповка выносится в чистый хелпер, чтобы одинаково закрыть смену цели и смену типа:

```ts
const restamp = (entry: DayEntry, habit: Habit): DayEntry => {
  if (habit.type === 'check') {
    return { value: entry.done ? 1 : 0, done: entry.done, completedAt: entry.completedAt };
  }
  const done = entry.value >= habit.target;
  return {
    value: entry.value,
    done,
    target: habit.target,
    completedAt: done ? entry.completedAt ?? Date.now() : null,
  };
};
```

`updateHabit` вызывает его только для ключа сегодняшнего дня и только если запись
существует. `toDateKey` импортируется из `@/lib/date` — этот модуль ни от чего не
зависит, цикла импортов не возникает.

Поведение после правки:

| Действие | Прошлый день (сделано 40 при цели 30) | Сегодня |
|---|---|---|
| Поднять цель до 50 | остаётся выполненным, показывает `40 / 30` | `40 / 50`, не выполнено |
| Опустить цель до 20 | остаётся выполненным, показывает `40 / 30` | `40 / 20`, выполнено |

## 3. Реконсиляция уведомлений

Расписание локальных пушей — отдельное состояние, которое синхронизируется только при
сохранении привычки в `HabitFormSheet`. Поэтому оно расходится со стором: `resetAll`
(`src/store/habits.ts:91`) чистит данные, но не расписание, и напоминания удалённых
привычек продолжают приходить. Тот же класс проблемы — переустановка и любой будущий
код, меняющий привычки в обход формы.

В `src/lib/notifications.ts` появляется функция, приводящая расписание в соответствие
со стором:

```ts
export async function reconcileNotifications(habits: Habit[]) {
  try {
    const scheduled = await Notifications.getAllScheduledNotificationsAsync();
    await Promise.all(
      scheduled
        .filter((n) => n.identifier.startsWith('habit-'))
        .map((n) =>
          Notifications.cancelScheduledNotificationAsync(n.identifier).catch(() => undefined),
        ),
    );
    for (const h of habits) {
      if (h.reminder && h.reminderTime) await syncHabitNotifications(h);
    }
  } catch {
    // планирование недоступно в Expo Go на части платформ
  }
}
```

Отмена идёт по префиксу `habit-`, а не через `cancelAllScheduledNotificationsAsync`,
чтобы не задеть уведомления другого рода, если они появятся. Функция идемпотентна:
повторный вызов даёт то же расписание.

Точки вызова:

- **Старт приложения** — в `src/app/_layout.tsx`, строго после гидратации persist.
  Если прочитать `habits` раньше, там будет пустой массив и реконсиляция снесёт все
  напоминания:

  ```ts
  useEffect(() => {
    const run = () => void reconcileNotifications(useHabits.getState().habits);
    if (useHabits.persist.hasHydrated()) {
      run();
      return;
    }
    return useHabits.persist.onFinishHydration(run);
  }, []);
  ```

- **После `resetAll`** в `src/app/(tabs)/profile.tsx` — с пустым списком, что отменяет всё.

Плата — перепланирование на каждом старте. При десятках привычек это незаметно.

## 4. Заморозка внутри стора

`freezeDay` пишет дату без проверок, а `canFreezeDay` вызывается только из UI, так что
правило можно обойти. Проверка переезжает в стор: если день уже заморожен или
`canFreezeDay` возвращает `false`, действие ничего не делает. UI продолжает показывать
доступность через `canFreezeDay`, для пользователя ничего не меняется.

Там же лечится DST. Сейчас (`src/lib/habits.ts:77`) разница дат сравнивается в
миллисекундах с `7 * 86400000`, поэтому на переходе времени семидневный зазор становится
6.96-дневным и проверка врёт. Обе даты нормализуются на полдень, разница округляется до
календарных дней — час туда-сюда перестаёт влиять. Само правило («другая заморозка ближе
чем 7 дней») не меняется.

## 5. Лучшая серия

`src/app/(tabs)/profile.tsx:26` берёт максимум из `streakOf` — то есть самую длинную
из **текущих** серий, а подписывает это «лучшая серия». Настоящий `bestStreakOf` из
`src/lib/stats.ts` не используется нигде. Профиль переключается на `bestStreakOf`;
подпись становится правдой, мёртвый экспорт — живым. Стоимость по вычислениям та же,
что сейчас.

## 6. Типографика

Playfair Display заменяется на **Yeseva One** — высококонтрастную декоративную антикву
в духе модерна. Manrope в интерфейсе остаётся.

Порядок работ:

1. Установить `@expo-google-fonts/yeseva-one`.
2. **Сначала проверить кириллицу**: отрендерить образец `Дисциплина 40/50 стр Пн Вт Ср`
   и убедиться, что глифы настоящие, а не подстановка системного шрифта. Проверить это
   заранее не удалось: `fonts.googleapis.com` недоступен из окружения, поиск в вебе тоже.
   Если кириллицы нет — Playfair Display остаётся, и вопрос выбора шрифта возвращается
   на обсуждение.
3. В `src/theme/tokens.ts` оба токена `display` и `displayBold` указывают на
   `YesevaOne_400Regular`: у шрифта одно начертание. Так все существующие места вызова
   остаются нетронутыми.
4. Обновить `useFonts` в `src/app/_layout.tsx`, убрать зависимость
   `@expo-google-fonts/playfair-display`.

У Yeseva One нет курсива, поэтому наклонные цитаты (`quote` в профиле,
`manifestoText` в `HabitDetailSheet`) отрисуются прямым начертанием. Это приемлемо.

## 7. Версия SDK в документации

`README.md` пишет «Expo (SDK 57)» в заголовке и «настроен на Expo SDK 54» в примечании,
`AGENTS.md` требует читать документацию `v57.0.0`, а установлен `expo@54.0.37`. Оба файла
приводятся к 54. Иначе инструкция гонит агента читать документацию не той версии.

## Принятые ограничения

- **`unit` не снимается в запись дня.** Смена «стр» → «км» переподпишет прошлые дни.
  Меняя единицу измерения, пользователь переопределяет саму привычку, а не её цель.
- **Историю до миграции восстановить нечем.** Записи, созданные раньше, получат
  `target` текущей цели: данных о прошлых целях в сторе нет. История «застынет» по
  сегодняшнему значению один раз, дальше будет защищена. Ветка `?? h.target` в `isDone`
  остаётся страховкой от битых данных.
- **Правило заморозки не меняется** — только переезжает в стор и перестаёт зависеть от
  DST. Переход на бюджетную модель («доступно 2 заморозки») — отдельный продуктовый
  вопрос.

## Проверка

Тестовой инфраструктуры в объёме нет, поэтому проверка — типы плюс сценарии руками:

- `npx tsc --noEmit` проходит чисто;
- четыре вкладки на месте, «Сегодня» открывается с таббаром, переключение работает;
- образец кириллицы в Yeseva One рендерится настоящими глифами;
- цель 30 → отметить выполнение → поднять цель до 50: прошлый день остаётся выполненным
  и показывает `/30`, сегодняшний показывает `/50`;
- включить напоминание, сбросить данные, убедиться, что запланированных пушей не
  осталось — через временный вывод длины `getAllScheduledNotificationsAsync()`, иначе
  это ничем не подтвердить;
- заморозить пропущенный день, попробовать заморозить соседний — второй не проходит;
- «лучшая серия» в профиле не уменьшается после того, как текущая серия сорвалась.

## Порядок коммитов

В репозитории нет ни одного коммита, а в индексе 15 файлов шаблона Expo в состоянии
«добавлен и удалён». Поэтому:

1. `git add -A`, затем первый коммит — текущее состояние как отправная точка.
2. Эта спека.
3. Коммиты реализации по плану.

Так диff правок читается отдельно от первичного импорта, а не растворяется в нём.
